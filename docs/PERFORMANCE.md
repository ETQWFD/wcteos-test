# wcteos 测试版 内核运行报告

## 一、测试环境

- QEMU 6.2 + OVMF（x86_64），TCG 纯软件模拟，无 KVM（沙箱内 `/dev/kvm` 不存在）
- 虚拟机配置：384MB 内存、单核、IDE 磁盘（FAT32 镜像）、e1000 或 rtl8139 网卡
- 串口日志与 screendump 截图为唯一取证手段，所有数据来自实际启动，不是估算

## 二、启动时序（串口记录）

固件加载 BOOTX64.EFI → 内核入口 → 磁盘枚举（ATA identify）→ PCI 枚举（6 个设备）→ PS/2 初始化 → 网络探测与 DHCP → 音频探测 → 基准 → 桌面。

- 从固件交棒到桌面首帧：约 20~26 秒（TCG 下波动主要来自指令翻译与宿主调度，不是内核本身）
- 同一镜像连续 10 次启动均进入桌面，无黑屏、无重启；`/wct/autogui` 存在时跳过命令行直进图形界面

## 三、内存吞吐实测（仅报周期数，不换算带宽）

`bench_report()` 用 rdtsc 测 1MB 拷贝与 1MB 填充，输出“每 MB 消耗的 TSC 周期”：

```
bench: copy=3274108 cyc/MB   fill=645758 cyc/MB     (一次启动)
bench: copy=10495550 cyc/MB  fill=7267399 cyc/MB    (另一次启动，同镜像同参数)
bench: copy=4503762 cyc/MB   fill=1160289 cyc/MB
```

同一镜像的周期数相差可达 3 倍以上。原因是 TCG 把每条客户机指令翻译成宿主指令，宿主机调度、缓存与翻译块命中率都会改变 IPC，而 rdtsc 在 TCG 下本身也由宿主时钟驱动。**这组数字只能说明“拷贝比填充慢”这一代码层面的相对关系，不能当作真实带宽，也不能与任何实体机或其它操作系统比较。**

因此本报告不再给出 MB/s、也不再给出“比普通系统快”的结论。之前的版本用 Stall 反推 TSC 频率得到的“2602MHz”是错误口径：QEMU 的 TSC 频率由配置预设，Stall 与 TSC 彼此独立，反推出来的只是两个时钟的比值，不是 CPU 主频。该数字已从代码与报告中删除。

## 四、网络

`net_ip`、`net_gw`、`net_mask` 全部由 DHCP 取得，代码里没有写死 10.0.2.15 或 10.0.2.2。ARP 校验的目标是 DHCP option 3 返回的网关；拿不到地址就不发 ARP，状态行显示 `arp:no`。

- e1000：`net: e1000 52:54:00:12:34:56 ip=10.0.2.15 link:up arp:ok rx:3 tx:3`，DHCP 与 ARP 往返均通过
- rtl8139：驱动完成复位、MAC 读取、收发环初始化，抓包可见 DISCOVER/OFFER 往返；但 8139 接收环在本沙箱 slirp 下的多帧连续读取不稳定，ARP 应答时常读不到，状态行会如实显示 `arp:no`。该路径仍需在实体 8139 网卡上复测，目前不宣称“已完全可用”。

## 五、图形与输入

- 双缓冲：`cmd_gui` 用 AllocatePool 申请整屏后备缓冲，绘制全部落在 RAM，`gfx_present` 按行批量拷入显存；分配失败才退回直写。这是原有的实现，本轮未改动，也不以函数名充当“优化成果”。
- 光标：黑色箭头 + 白色描边，深色壁纸上仍可见；移动时只重绘光标与脏矩形，不整屏刷新。
- 输入源优先级：Simple Pointer → Absolute Pointer → HID → PS/2；QEMU 下实测走 PS/2 i8042 兜底（`mouse: PS/2 i8042 ready (fallback)`）。
- 桌面：6 个内核内手绘图标，双击打开对应窗口；右键任务栏开任务管理器，右键桌面换壁纸。
- 任务栏：开始菜单、窗口按钮、音量、网络、HH:MM 时钟（UEFI GetTime）。

## 六、中文与字体

界面文案全部为 16×16 点阵，编译期生成进内核，运行时不需要字体文件。本轮按源码实际出现的字符重新生成，共 581 个字形，覆盖桌面、面板、任务管理器、关于、运行框的全部中文字符；源文件中不再有缺字。

## 七、音频

HDA 控制器可复位、GCAP 可读（0x00004401），codec 枚举结果为 0，GET PARAMETER 无应答。播放通路未打通，设置面板与状态行如实标注。本轮未取得进展。

## 八、结论与限制

- 已实测可用：U 盘镜像启动到桌面、桌面与窗口交互、任务管理器结束进程、壁纸与主题切换、e1000 的 DHCP + ARP、ISO 与 U 盘镜像生成
- 未完成：HDA codec、无线网卡、完整安装程序（当前是直接 FAT32 引导，不是装到硬盘并写 UEFI 启动项）、8139 在 slirp 下的连续收包
- 无 KVM，无法给出有意义的性能对比结论；任何“比普通系统快”的说法在本环境下都不成立
