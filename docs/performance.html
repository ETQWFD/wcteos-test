内核运行报告

本报告只写实测到的东西，并给出复现命令。没有 KVM 的纯软件模拟环境下，任何“比别的系统快”的说法都不成立，所以这里不下这个结论。

一、测试环境

项目值
虚拟化QEMU 6.2，-accel tcg，无 /dev/kvm
内存 / CPU384MB，单核
固件OVMF 4MB（CODE + 每次全新的 VARS）
磁盘48MB FAT32 ESP，IDE
网卡e1000（另有 rtl8139 驱动）
显示GOP 1024×768，32 位帧缓冲
镜像wcteos-0.9-test.iso / 同一份 BOOTX64.EFI

二、复现命令

cp /usr/share/OVMF/OVMF_VARS_4M.fd vars.fd
qemu-system-x86_64 -m 384 -smp 1 -display none -no-reboot -accel tcg \
  -drive if=pflash,format=raw,readonly=on,file=/usr/share/OVMF/OVMF_CODE_4M.fd \
  -drive if=pflash,format=raw,file=vars.fd \
  -blockdev driver=file,filename=esp.img,node-name=e,locking=off \
  -blockdev driver=raw,file=e,node-name=ed \
  -device ide-hd,drive=ed,bus=ide.0,unit=0 \
  -netdev user,id=n0 -device e1000,netdev=n0 \
  -serial file:serial.log -monitor none

等 40 秒左右读 serial.log。图形截图用 monitor 的 screendump，路径必须是绝对路径。

四、rdtsc 原始计数（不作性能结论）

同一次运行的 bench 行：
copy=3,958,994 cyc/MB   fill=648,771 cyc/MB

另一次、同一镜像：
copy=10,495,550 cyc/MB  fill=7,267,399 cyc/MB

两次差 3 倍以上。原因是 TCG 把每条指令翻译成宿主指令，宿主进程被调度走、缓存被挤占都会让计数剧烈波动。因此：

  • 不能把 cyc/MB 换算成 MB/s；
  • 不能用这些数反推 CPU 主频；
  • 不能用它证明“比普通系统快”。

五、能确认与不能确认

能确认不能确认
内核能在 OVMF 下启动进桌面真机上的启动耗时
鼠标、键盘、GOP 图形可用与 Windows/Linux 的速度对比
e1000 下 DHCP 与 ARP 可用rtl8139 在真实网络下的稳定性
.wct / WCTX 模块能加载执行音频输出是否可用
文件读写、属性、删除保护可用.wcte 与 WIM 的压缩速度对比

要做速度对比，必须在同一台真机、同一块盘、同一份测试程序上跑两组镜像，并给出多次采样的中位数。当前环境不具备这个条件，所以报告到此为止。

六、已知问题清单

  • ISO 的 El Torito 在部分沙箱 OVMF 里被跳过，会落到内置 shell；U 盘镜像可直接启动。
  • HDA 音频无 codec 应答，没有可验证的声音输出。
  • 无线网卡没有驱动。
  • 安装程序尚未实现“写入硬盘 + 注册 UEFI 启动项 + 自动重启”的完整流程。
  • 没有 KVM，性能结论一律不成立。
