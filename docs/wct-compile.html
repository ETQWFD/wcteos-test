.wct 可执行文件编译手册

这份手册写给第一次编译 wcteos 模块的人。照着从第一节做到第九节，你会得到一个能被系统识别、双击就能运行的 hello.wct。每一步都给完整命令，不省略参数。

先说清楚：.wct 不是裸二进制。文件 = 24 字节 WCT1 头 + 扁平机器码；头里有 magic、基址、入口偏移、代码长度和 CRC32，内核加载前会校验。可选的 WCTX 容器再把整个 WCT1 镜像 XOR 混淆一层。WCTX 是混淆，不是加密，密钥随文件保存，只能挡住随手反汇编。

一、你要准备什么

项目要求
操作系统Windows 10/11（推荐，下面给 MSYS2 步骤）或 Linux（Ubuntu/Debian 系）
编译器mingw-w64 的 x86_64 GCC + binutils，不能用普通 Linux ELF 编译器
Python3.8 以上，用来封 WCT1 头
运行环境wcteos 测试版 ISO 或 U 盘镜像，QEMU 或真机

二、安装工具链

A. Windows（小白推荐）

  1. 打开 https://www.msys2.org 下载安装包，一路默认安装到 C:\msys64。
  2. 在开始菜单里打开 MSYS2 UCRT64（不是 cmd，也不是 PowerShell）。
  3. 粘贴下面两行，等它跑完：
pacman -Syu
pacman -S --needed mingw-w64-x86_64-gcc mingw-w64-x86_64-binutils python

装完验证（能打印版本号就说明成功）：

x86_64-w64-mingw32-gcc --version
x86_64-w64-mingw32-ld --version
python --version

B. Linux（Ubuntu / Debian）

sudo apt-get update
sudo apt-get install -y gcc-mingw-w64-x86-64 binutils-mingw-w64-x86-64 python3

验证：

x86_64-w64-mingw32-gcc --version
x86_64-w64-mingw32-objcopy --version
如果提示 command not found，说明上一步没装成功；先把安装命令重跑一遍，不要继续往下做。

三、写第一个模块 hello.c

新建一个文件夹，例如 D:\wct-build（Linux 下 ~/wct-build），在里面新建 hello.c，内容一字不改地复制：

/* hello.c —— 最小 wcteos 模块 */
typedef unsigned long long u64;

typedef struct {
    void (*puts)(const char *s);      /* 输出字符串 */
    void (*putu)(u64 v);              /* 输出无符号整数 */
    void (*clear)(void);              /* 清屏 */
    u64 version;                      /* 内核 API 版本，当前为 1 */
    const char *kernel_tag;           /* 例如 "WCT-Kernel" */
} WCT_API;

int wct_main(WCT_API *api)            /* 入口名必须是 wct_main */
{
    api->puts("hello from my first .wct module\r\n");
    api->puts("kernel tag: ");
    api->puts(api->kernel_tag);
    api->puts("\r\n");
    return 0;                          /* 返回值会打印到内核串口 */
}

约定：入口函数名必须是 wct_main，第一个参数是 WCT_API *，返回 int。API 表只能使用上面这 5 个字段，不要自己加字段猜布局。

四、编译成目标文件

在 hello.c 所在目录执行：

x86_64-w64-mingw32-gcc -ffreestanding -fno-stack-protector -fno-builtin \
    -mno-red-zone -O2 -c hello.c -o hello.o

每个参数的作用，别乱删：

参数为什么必须要
-ffreestanding告诉编译器没有操作系统和标准库，不生成对 printf/memcpy 的隐式调用
-fno-stack-protector内核不提供栈保护桩函数，开着会链接失败
-fno-builtin禁止编译器把循环优化成 memset/memcpy 调用
-mno-red-zoneUEFI 固件中断会踩坏红区，必须关掉
-O2优化级别，可用 -O2 或 -Os

五、链接并抽成扁平二进制

x86_64-w64-mingw32-ld -e wct_main --image-base 0x00400000 -o hello.elf hello.o
x86_64-w64-mingw32-objcopy -O binary hello.elf hello.bin

为什么要用 mingw 而不是 Linux 的 gcc -m64：模块运行在 Windows x64 调用约定下（第一个参数放 RCX），Linux 的 System V 约定把参数放 RDI，调进去会拿到错误指针，直接崩。这是最多人踩的坑。

为什么还要 objcopy：内核不解析 PE/ELF，只认连续机器码。objcopy 从最低有内容的段开始抽，所以下面算入口偏移要以段的 VMA 为基准，不能直接用链接基址。

六、算入口偏移

VMA=$(x86_64-w64-mingw32-objdump -h hello.elf | awk '$2==".text"{print $4; exit}')
SYM=$(x86_64-w64-mingw32-nm hello.elf | awk '/ T wct_main$/{print $1}')
OFF=$((0x$SYM - 0x$VMA))
echo "VMA=$VMA SYM=$SYM ENTRY_OFF=$OFF"

正常情况下 OFF=0。如果这里算错，内核会跳到代码中段，表现为 #UD、重启或死机——这是第二常见的坑。

七、封 WCT1 头

新建 build-wct.py，内容完整复制：

import struct, sys, zlib

if len(sys.argv) not in (4, 5):
    print("usage: build-wct.py code.bin entry_offset out.wct [base]")
    sys.exit(2)

code = open(sys.argv[1], "rb").read()
entry_off = int(sys.argv[2], 0)
base = int(sys.argv[4], 0) if len(sys.argv) > 4 else 0x00400000

hdr = bytearray(24)
hdr[0:4] = b"WCT1"                 # magic
hdr[4] = 1                         # 版本
hdr[5] = 0                         # 保留
struct.pack_into("<H", hdr, 6, 1)  # 段数
struct.pack_into("<I", hdr, 8, base)
struct.pack_into("<I", hdr, 12, entry_off)
struct.pack_into("<I", hdr, 16, len(code))
struct.pack_into("<I", hdr, 20, zlib.crc32(code) & 0xFFFFFFFF)

open(sys.argv[3], "wb").write(hdr + code)
print("wct written:", sys.argv[3], "code=", len(code), "entry=+0x%X" % entry_off)
python build-wct.py hello.bin $OFF hello.wct 0x00400000

头字段表（和内核 wctmod.c 一一对应）：

偏移类型含义
0char[4]WCT1
4u8版本 = 1
5u8保留 = 0
6u16段数 = 1
8u32首选加载基址（示例 0x00400000）
12u32入口偏移（相对代码起点）
16u32代码长度（字节）
20u32代码 CRC32

八、打包成 WCTX（可选，但推荐）

把 WCT1 镜像再包一层，文件开头变成 WCTX，直接看是乱码：

./wctpack hello.wct hello.p.wct 0xA5C3E71B
# 不写密钥就用默认 0xA5C3E71B

内核加载顺序：看到 WCTX → 取 32 位密钥 → 解 XOR → 得到完整 WCT1 镜像 → 继续校验 CRC 与长度。所以打包不会破坏校验，也不能只打包一半。

再说一遍：这是混淆。密钥就写在文件里，任何人拿到文件都能解。要真正防止逆向，需要服务端签名或硬件密钥，这版没做。

九、放进镜像并运行

方法一：改 ESP 镜像（QEMU 测试最快）

mcopy -o -i esp.img hello.p.wct ::/wct/HELLO.WCT

注意 FAT 短文件名：内核按名字查找，建议用 8.3 形式（HELLO.WCT），长文件名在部分工具下会变成 HELLO~1.WCT 而找不到。

方法二：真机 / U 盘：挂载 U 盘的 EFI 分区，把文件复制到 \wct\ 目录即可。

运行：终端输入 run \wct\HELLO.WCT，或在文件管理器里双击它。成功时串口输出：

  [wct] loading module at 0x00400000  (fixed base)  entry=+0
  hello from my first .wct module
  kernel tag: WCT-Kernel
  [wct] module returned 0

十、常见错误对照表

现象原因处理
undefined reference to ...用了 libc 函数或没关栈保护只用 API 表；确认 -ffreestanding -fno-stack-protector -fno-builtin
加载后立即 #UD / 重启入口偏移算错，跳进指令中段按第六节用 VMA 与符号地址重算 OFF
checksum mismatch文件被截断，或打包时长度写错重新 objcopy 与 build-wct.py，不要手工改头
run: script not found路径不对，或 FAT 里是短名别名用 ls \wct 看真实名字，改用 8.3 名
模块里输出乱码字符串不是 ASCII，API 只接受 ASCII中文请走内核图形 API，模块输出保持英文
能加载但返回非 0模块自己 return 了别的值正常，返回值会原样打印，便于调试

十一、多文件与限制

x86_64-w64-mingw32-gcc -ffreestanding -fno-stack-protector -fno-builtin \
    -mno-red-zone -O2 -c a.c -o a.o
x86_64-w64-mingw32-gcc -ffreestanding -fno-stack-protector -fno-builtin \
    -mno-red-zone -O2 -c b.c -o b.o
x86_64-w64-mingw32-ld -e wct_main --image-base 0x00400000 -o hello.elf a.o b.o
  • 没有堆分配器，缓冲区用静态数组或栈。
  • 没有浮点、SSE、异常处理，越界写会把客户机打挂。
  • 不能调 UEFI Boot Services，也不能用 Linux 系统调用。
  • 代码必须位置无关：首选基址被占用时内核会重定位到任意页。
